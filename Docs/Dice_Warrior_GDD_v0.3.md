## 새 경기 v5: 굴림·보관·리롤·실행 (2026-10-24)

[v5 원안](Dice_Warrior_V5_Dice_Roll_Hold_Reroll_Skill_UI_Implementation_Plan_v0.1.md)의 제품 요구사항을 [V5 PLAN](Plans/V5_DICE_COMBAT_09_PLAN.md)에 정리했다. 구현·자산 연결·검증 상태는 [REPORT](Reports/V5_DICE_COMBAT_09_REPORT.md)를 따른다. 기존 v1~v4는 저장된 정의로 재개하며 명시적인 새 게임만 `shared-world-preview-5`를 적용한다. 6스탯·속성·계정 성장과 공동 모험 규칙은 아래 v4 기준을 재사용한다.

- 전투는 최초 굴림 → 보관/해제·리롤 → 실행으로 나눈다. 각 입력은 저장되는 독립 명령이며 실행할 때만 기술·적 반격·행동턴을 진행한다. 저장 성공 전에 결과를 공개하지 않는다.
- 매 행동턴 리롤1회, 보관하지 않은 주사위만 원래 슬롯 순서로 다시 뽑는다. 보관/해제는 RNG를 소비하지 않는다. 모두 보관했거나 남은 리롤이0이면 리롤 버튼은 비활성화되고 실행은 가능하다.
- 시작 주사위는 balanced=`검/지팡이/불/방패/직업전용/꽝`, arcane=`검/지팡이/지팡이/불/직업전용/꽝`, steel=`검/검/지팡이/방패/직업전용/꽝`. 모두 정확히6면이고 중복면도 물리 인덱스로 구별한다. 첫1개에서 완주 보상으로 최대3개가 된다.
- 꽝은 스탯·피해·보호·조합에 참여하지 않는다. 전부 꽝이어도 실행할 수 있고 적 행동은1회다. 조합은 3눈 우선, 없으면 우선순위가 높은2눈 하나와 남은단일, 동률은 SkillId 순이다. 예상 발동은 현재 눈만으로 실제 보호막 흡수·피해·처치 후 생략 순서를 계산한다.
- 공용9기술의 기존 수치는 유지한다. 전용 시험 기술은 검사 단일 물리4/검 조합14(힘70%+민첩30%), 룬술사 단일 번개3(지능60%+정신40%)/지팡이 조합15(지능70%+정신30%), 수호자 단일 보호5/방패 조합12(체질60%+정신40%)다. 표기값은 기본값이며 계수·장비·패시브가 더해진다.
- AI `v5-keep-nonblank-1`은 현재 눈에 꽝이 있으면 비꽝을 보관하고 꽝만1회 리롤한다. 없으면 즉시 실행한다. 인간과 같은 합법 입력·RNG 규칙을 사용한다.
- 사용자 승인으로 v5 전투는 최대20행동턴이다. 전체2048명령·4MiB는 유지하며 남은 진행과 매턴 리롤 공간을 먼저 확보한다. 보관/해제는 턴당12회이고 예약 공간을 침범할 때만 추가 제한한다. 구형 최대64턴은 유지한다.
- 전투 화면은 굴림/보관 영역, 현재 예상 기술, 왼쪽 리롤·오른쪽 실행을 표시한다. 6면 전개도는 로비·전투·획득 후보에서 열고 현재 물리면을 강조한다. 지도·순위·상세는 정보창으로 제공하며 조회는 명령/RNG/저장을 바꾸지 않는다.
- 영구 보상0, C6 정산·Firebase·신의 권능·세계관 변경은 이번 범위 밖이다. B0/C7 도구는 계속 동결 v4 기준선만 검사하며 v5 밸런스 결과로 해석하지 않는다.

## 보존하는 v4 기준: 태그·6스탯·4속성 (2026-10-22)

[태그·스탯·속성 원안](Dice_Warrior_Tag_Stat_Element_Integration_Design_v0.1.md)을 현행 RGB v3와 대조하고 사용자 답변을 [TAG_STAT_ELEMENT_05 PLAN](Plans/TAG_STAT_ELEMENT_05_PLAN.md)에 확정했다. 원안의 “새 v3”는 이미 사용 중이므로 별도 `shared-world-preview-4`로 구현한다. 실제 완료 증거와 미검증은 [REPORT](Reports/TAG_STAT_ELEMENT_05_REPORT.md)를 따른다. 기존 v1~v3 경기는 저장된 정의로 재개하며 확인 후 새 게임만 v4다.

| 모험가 | 힘 | 민첩 | 체질 | 지능 | 정신 | 행운 | 계정 보정 전 HP |
|---|---:|---:|---:|---:|---:|---:|---:|
| 방랑 검사 | 7 | 6 | 5 | 3 | 5 | 4 | 60 |
| 룬술사 | 3 | 4 | 5 | 7 | 6 | 5 | 60 |
| 성채의 수호자 | 6 | 3 | 7 | 3 | 7 | 4 | 72 |

- HP=`30+체질×6+계정growth×5`. 필요 XP=현재 레벨×8, 6스탯은 레벨마다+1. 현재HP에는 파생 최대HP 증가분만 더하므로 기존HP+6을 중복 적용하지 않는다. 인간과 AI의 기존 계정 보정·시작 장비/주사위는 동일하다. 행운은 명시된 보물5사건에 `floor(행운/5)` 추가 골드를 한 번 지급한다.
- 태그는 StableId·표시명·허용 Owner·단일 부모를 가진 분류/조회 자료다. Skill Identity와 GrantedAction, Source/Equipment/Place/Target/DamageComponent를 분리한다. 장비/대상 태그가 행동에 자동 전달되지 않는다. ALL/ANY/NONE의 Owner와 자식 포함 여부를 명시한다. 같은 태그의 여러 출처는 원본에 보존하지만 Has는 한 번만 참이다.
- 유효 태그는 체크포인트별 읽기 사본이다. 기본 충돌은 거절하며 명시 Priority에서만 승자를 고르고 모호한 동률은 거절한다. 한 출처 제거는 그 출처만 제거하고 억제된 다른 출처를 복원한다. 미등록/순환/Owner/ID/상한 오류는 저장 전 거절한다.
- 수치 Binding은 스냅샷을 읽기만 하며 태그가 자체로 능력을 발동하지 않는다. 출처·규칙·대상 중복은 한 번, 서로 다른 내용의 중복은 거절한다. Flat→PercentAdd 합산→서로 다른 FinalMultiply 그룹→상성 순으로 만분율 정수 유리수를 합성하고 최종 한 번 반올림한다. 같은 그룹의 중첩 정책은 Stackable/UniqueBySource/HighestWins 중 하나로 고정한다.

| 기술 | 피해 타입 | 기본 피해에 더하는 스탯 | 기본 보호량에 더하는 스탯 |
|---|---|---|---|
| 베기 | 물리 | 힘70%+민첩30% | — |
| 마력탄 | 번개 | 지능60%+정신40% | — |
| 불꽃 | 화염 | 지능100% | — |
| 방어 | — | — | 체질60%+정신40% |
| 검기 | 냉기 | 힘40%+민첩30%+지능30% | — |
| 화염탄 | 화염 | 지능70%+정신30% | — |
| 수호 베기·성채 베기 | 물리 | 힘40%+체질30%+정신30% | 체질60%+정신40% |
| 화염 검기 | 화염 | 힘40%+지능60% | — |

- 기존 기술 기본 피해/보호량, 4종 기호, 3눈 우선·2눈 부분조합, 보호막과 처치 뒤 생략은 유지한다. 기호와 피해 타입은 서로 독립이며 주사위 면을 추가하지 않는다. 검사 강철 계열 피해+1, 룬술사 비전 계열 또는 화염 피해+1(OR 한 번), 수호자 보호량+1이다. 장비5종의 기존 보너스는 출처별 Binding으로 한 번만 계산한다.
- 일반 적10종+최종시련에 공격 타입과 약점/저항을 동결했다. 적별 약점·저항은 각 최대1개, 동일 타입 중복 금지. 약점+20%, 저항−15%이며 예시 `100×1.15×1.2=138`, `100×1.15×0.85=98`이다. 원소 변환은 무기 한 개의 명시 기능으로 타입과 DamageComponent 태그를 함께 바꾼 뒤 보정을 평가한다. 초기5장비에는 변환 효과를 새로 붙이지 않는다. 기본 모험가 속성 저항은0이다.
- 치명타/회피 확률은 이번0%, 민첩 자동 회피 없음. Reaction 큐/연쇄 발동/상태이상·DOT·추가 속성은 구현하지 않는다. 기존4개 RNG의 소비 경로를 유지하며 상세 조회·AI 상성 평가에서 난수를 굴리지 않는다. AI는 보유면에 따른 상성과 행운 보물을 참고하고 인간과 같은 전투·보상 함수를 실행한다.
- 로비/경기 상세에 6스탯·HP 출처·기술 타입/계수·적 상성·태그/보정 출처를 표시한다. v4 전투는 별도 typed 결과를 저장하고 기존 이동/주사위/스킬 연출에는 표시 사본만 전달한다. 런타임 판정을 UI가 다시 실행하지 않는다.
- 신격·영구 권능/업적 해금·C6 서버 정산·Firebase는 후속이다. 새 경기 영구 보상0, 구형1인 active 계정 성장 구매 보류 정책, 서버v1 계약은 유지한다.

## 보존된 모험가 RGB v3 계약 (2026-10-22)

[성장 방향 GDD v0.2](Dice_Warrior_God_Adventurer_Growth_Direction_GDD_v0.2.md)의 방향과 사용자 답변을 [GROWTH_04 PLAN](Plans/GOD_ADVENTURER_GROWTH_04_PLAN.md)에 확정했다. 이번 구현은 RGB 전투·기본 제공 모험가 선택/고유 능력·경기 내 자동 성장·상세 화면이다. 실제 완료 증거는 [REPORT](Reports/GOD_ADVENTURER_GROWTH_04_REPORT.md)를 따른다.

| 기본 제공 모험가 | 기본 HP | 무력 STR | 수호 GRD | 비전 ARC | 고유 능력 |
|---|---:|---:|---:|---:|---|
| 방랑 검사 | 60 | 6 | 4 | 4 | 강철 태그 피해 기술 +1 |
| 룬술사 | 60 | 4 | 4 | 6 | 비전·불 태그 피해 기술 +1 |
| 성채의 수호자 | 60 | 4 | 6 | 4 | 보호막 발생 기술 보호량 +1 |

- 위 값은 사용자 승인 시험값이다. 무력 #E56C64, 수호 #52B987, 비전 #7297ED를 텍스트/아이콘과 함께 표시한다. HP는 별도 생존 수치다.
- 베기·검기·수호 베기·성채 베기는 기본 피해+무력, 마력탄·불꽃·화염탄은 기본 피해+비전, 화염 검기는 기본 피해+floor((무력+비전)/2)다. 보호막은 기본 보호량+수호다. 일치하는 태그 장비·모험가 패시브를 더하고 기존 보호막 흡수/처치 뒤 생략/적 반격1회를 적용한다. 기본 효과0인 기술에 보너스만으로 새 피해/보호 효과를 만들지 않는다.
- 모험가 필요 XP는 현재 레벨×8이다. 레벨 상승 시 최대/현재 HP+6, 무력·수호·비전 각+1. 계정의 기존 growth당 시작 HP+5를 보존한다. AI는 전쟁=검사·지혜=룬술사·행운=수호자이며 인간과 같은 계정 HP 보정/시작 주사위/무기를 적용한다. 모험가별 기본 스탯과 패시브는 서로 다르다.
- 로비의 `모험가 선택`은 다음 경기의 선호만 변경한다. 별도 `adventurer-selection.json`에 ID/revision/체크섬을 저장하며 진행 중 경기·기존 서버 프로필을 바꾸지 않는다. 손상/저장 실패 시 원문을 보존하고 새 게임/선택을 제한하되 기존 경기는 이어갈 수 있다.
- `출전 능력치`는 예상 시작값, 경기의 `능력치 상세`는 동결된 모험가의 기본값·계정 HP 보정·런 레벨·최종 RGB·장비의 태그별 보정을 표시한다. `주사위·스킬`은 현재 보유 주사위6면과 실제 가능한 기술/계수를 보여준다. 상세 화면은 RNG/경기 상태를 바꾸지 않는다.
- 새 규칙은 `shared-world-preview-3`, 별도 `SharedWorld/Content/shared-world-preview-3.json`에서 시작 때 동결한다. 기존 v1/v2 저장과 콘텐츠·골든은 유지하고 RGB 변경은 경고 확인 후 새 게임부터 적용한다. 구형 상세에는 기존 위력/수호 규칙임을 표시한다.
- 신은 계정의 주체, 모험가는 경기의 출전자라는 방향을 유지한다. 이번에는 신격/신 XP/권능 트리·영구 포인트·업적 해금·재굴림을 구현하지 않는다. 권능 준비는 향후 로비에서 하며 시작 시 동결하고, 영구 보상/해금은 공동 경기 서버 재현 C6와 함께 다룬다. 경기 XP를 신의 영구 포인트로 지급하지 않는다.

## 현행 메인: AI 공동 모험 (2026-10-22)

사용자가 **첫 플레이 가능 버전 C0~C5**를 확정한 뒤 기존1인 모험판을 제거하고 AI 공동 모험을 메인으로 전환하도록 지시했다. [메인 전환 REPORT](Reports/SHARED_WORLD_MAIN_02_REPORT.md)와 [C0~C5 REPORT](Reports/SHARED_WORLD_COMPETITION_01_REPORT.md)는 선행 구현 증거다. 현재 종료·새 게임·부분 조합은 [FLOW_COMBO_03 PLAN](Plans/SHARED_WORLD_FLOW_COMBO_03_PLAN.md) / [REPORT](Reports/SHARED_WORLD_FLOW_COMBO_03_REPORT.md)를 따른다. 아래 SymbolLoop v1 자료는 공유 전투와 기존 서버/저장 기록을 설명하는 보존 계약이며 플레이 가능한 별도1인 모드는 아니다.

- 한 사람의 개인 경기 안에서 인간1명과 AI3명이 같은 네임드12칸 보드를 사용한다. 장소 ID/순서는 변하지 않고, 위치·HP·성장·장비·주사위·방문·사건·난수는 참가자별이다. 같은 칸에 함께 있어도 사건·상점·보상은 독립이다.
- 이동 D6가 출발점을 넘으면 0번에서 멈추고 초과 눈을 버린다. 각 장소는 고유 후보군에서 개인 완주 단계와 조건에 맞는 2~3개 사건 제안을 착지 시 고정한다. 재표시·저장 복구로 다시 추첨하지 않는다.
- 인간이 이동한 뒤 사건까지 마치면 전쟁·지혜·행운 AI가 순서대로 각자 이동/사건을 끝낸다. 인간과 AI는 같은 비용·주사위·전투·보상 함수를 사용한다. 인간 사건의 마지막 명령과 AI 세 명의 결과는 하나의 후보 저장으로 확정된다. 인간이 먼저 완료/탈락하면 다음 AI 라운드를 관전할 수 있다.
- 시작 프로필은 기존 Mock 서버 조회 성공 뒤 복사하고 인간의 계정 성장 전력을 AI에도 동일하게 적용한다. 각자 첫 두 바퀴 보상으로 주사위를1→2→3개로 늘리고 마지막 바퀴에서 장비를 고른 뒤 최종 시련에 도전한다. v2/v3/v4 경기는 3눈 조합이 없을 때 2눈 조합과 남은 기본기를 함께 실행하며 장비3칸 판정은 유지한다.
- 개인3바퀴 뒤 최종 시련을 끝내거나 탈락하면 개인 진행 종료. 전원 완료/탈락 또는30세계라운드에서 경기 종료. 하나의 전투는 인간/AI 모두64턴 상한으로 교착을 종료한다. 세계라운드와 전투턴은 별개다.
- 순위는 최종시련성공→완주수→명예→남은HP 내림차순이며 모두 같으면 공동순위다. 명예는 콘텐츠 시험값(일반전투1/정예2/최종시련5/발견1)을 사용하고 원천 사건 ID로 중복을 방지한다. 명예는 영구 성장 재화가 아니다.
- 새 경기 규칙은 위 태그·6스탯 개편의 v4이며 세계 `named-world-1`, AI `shared-world-ai-1`, 순위 `shared-world-score-1`은 유지한다. 이전 `SharedWorld/Content/shared-world-preview-1.json`은 v2 참조 콘텐츠로 보존한다. 기존 경기의 규칙은 재개해도 저장된 버전으로 유지한다. Unity와 별도 .NET 프로젝트는 같은 순수 C# 소스를 사용한다.
- Title에서 공동 모험 로비가 바로 열린다. 출전 주사위·무기 선택, 영구 성장 조회/구매, 새 게임/경기 이어하기를 제공한다. 진행 중 `모험 종료`는 저장된 진행을 보존하고 로비로 돌아간다. 기존 경기가 있으면 `새 게임`은 초기화 경고와 취소/확정을 표시한다. 확인 후 최신 프로필 조회·새 경기 저장에 성공해야 현재 경기를 교체하며 재화·영구 성장·기존1인 기록은 유지한다. 취소·조회 실패·저장 실패·오래된 세션은 기존 진행을 교체하지 않는다. 네 말·개인 성적/사건·AI요약·숫자/기호/스킬 연출은 유지한다.
- 이전1인 진행 기록은 자동 종료·정산·삭제하지 않는다. 사용자가 **기록 보존·해당 계정의 영구 성장 구매 보류**를 선택했다. 이전 active run이 있어도 공동 모험 출전 선택/시작/재개는 가능하며, 영구 성장 보류 이유를 표시한다. 새 출전 선택은 기존 계정 진행과 분리 저장한다.
- 신규 체크포인트는 기존 endpoint+계정별 폴더 아래 `shared-world-preview-v1/checkpoint.json`(schema1)에 격리한다. 후보 복제→검증→원자 저장→공개, 명령ID/대상/revision/복구세대 검사, 손상 원문/백업·이전 완료 경기 보존을 사용한다. 새 게임으로 교체한 진행 중 원문은 `.restarted-*`, 완료 원문은 `.completed-*` 복구 사본에 남긴다. 기존 schema2와 서버 DB를 자동 이관하지 않는다.

**현재 새 경기의 영구 재화 지급은 0이다.** 순위/AI 최종 상태를 기존 v1 정산 API에 제출하지 않는다. 새 서버 시작 티켓·AI 재현 권한 정산은 C6, 대량 밸런스/성능·비용 보정은 C7이다. 실제 Firebase·실시간 PvP·외부 LLM·4눈 각성·신의 추가 전투 능력은 이번 범위가 아니다. 기존 v1의 M0~M4 서버와 정산은 계속 유지한다.

## 공유 전투 계약

공동 경기 v2/v3/v4는 전체 눈의 순서 무관 멀티셋과 정확히 일치하는 조합 기술 **한 개**를 먼저 선택한다. 3눈 전체 조합이 없으면 포함된 2눈 조합 한 개를 찾고, 남은 눈 기본기 뒤에 해당 조합을 실행한다. 예: 지팡이(비전)·지팡이·검 → 마력탄(비전 기본기)·검기. 후보가 여럿이면 콘텐츠 배열에서 먼저 등록된 조합을 고르며 각 주사위는 한 번만 소비한다. 부분 조합도 없으면 주사위 순서대로 모든 기본기를 실행한다.
보존된 SymbolLoop v1 및 이미 시작한 SharedWorld v1은 정확한 전체 조합만 선택하고 불일치하면 모든 기본기를 실행한다. 기존 경기의 저장·재현 결과를 바꾸지 않으며 새 v2 규칙은 경고를 확인하고 새 게임을 시작해야 적용된다.
기본기와 조합기는 같은 피해/보호막 계산을 쓴다. 장비는 기술 태그에 맞는 보너스만 준다.
수호는 보호막 기술의 효율이며 상시 피해 감소가 아니다.

- D1: 적 사망 이후 계획된 기본기·조합 기술은 `enemy-defeated`로 생략 기록. 계획·적용·생략을 구분한다. 죽은 적은 반격하지 않는다.
- D2: 적 보호막은 플레이어 기술 묶음 전체에서 차감하고 남은 양은 묶음 끝에 만료한다.
- 살아 있는 적은 예고된 공격/강공격/방어 중 하나를 한 번 실행한다. 플레이어 보호막은 반격/턴 종료 뒤 만료한다.
- 면 결과·기술 ID·효과·적 의도·턴 전후 HP/보호막을 저장한다. UI 재표시·재개는 확정 로그만 읽는다.

## 보존된 v1 캠페인·재현 계약

지역당 12칸: 시작 0, 사건 1..11. 이동 D6 1개, 착지 타일만 처리한다.
`위치 + 눈 >= 12`이면 위치 0의 완주 보상 대기로 전환하며 초과 이동을 버린다. 일반 타일 사건은 없다.
지역 보드는 시드와 지역 번호에서 파생한 별도 RNG로 한 번 생성하고 저장한다. 전투 RNG와 독립적이다.
각 보드에 전투·이벤트·보물·상점·휴식이 모두 존재한다.
완주 보상은 `runId:region:lap` ID로 한 번 확정한다. 지역 3의 보상도 보스 **진입 전** 받는다.

## 실행·저장·화면

Title.unity 하나에서 로비/보드/전투/보상/결과를 전환한다. 고정 UI는 Editor에서 작성한 프리팹, 반복 타일·선택지는 작성된 슬롯을 바인딩한다.

## 보드·주사위·스킬 표시 계약 (2026-10-21)

사각 둘레의 12칸에서 전사 말이 시계 방향으로 이동한다. 숫자 D6의 면이 회전·감속해 확정 눈을 보여준 뒤 말이 한 칸씩 튀며 이동한다. 출발점 통과 시 0번에 멈추고 초과 칸을 버린다. 사건 화면은 착지 후 열린다.

전투에서는 보유한 1~3개의 주사위가 실제 여섯 기호 면을 가진 입체 Canvas 메시로 회전한다. 정지 면은 저장된 결과다. 확정 로그에 따라 전체 조합 한 개, 기본기 묶음, 또는 남은 기본기 뒤 부분 조합을 순서대로 표시한다. 혼합 발동 안내와 각 기술의 SKILL/COMBO 표시를 구분한다. 검격/마법/화염/방어는 각각 기호·색·이동/충격 효과를 가지며 스킬 이름, 피해/보호막, 체력 바를 함께 갱신한다. 처치 뒤 생략된 스킬과 없는 반격은 표시하지 않는다. 적용된 플레이어 기술 뒤 기록된 적 공격/방어를 표시한다.

연출은 저장 성공 후 전후 상태와 턴 로그를 소비한다. 게임 RNG나 피해 계산은 재실행하지 않는다. 재생 중 명령 입력을 잠그고, 앱 비활성/백그라운드/화면 닫기/다시 불러오기는 최종 확정 상태로 복귀한다. 연출 중 종료해도 이미 저장된 결과를 다시 지급하지 않는다.

코드로 그린 벡터 아트와 입체 투영 방식이며 Rigidbody 물리 주사위·최종 캐릭터 아트·음향은 이번 범위에 포함하지 않는다. 세로 720×1280 기준 레이아웃을 가용 safe area에 균일 축소/확대한다. 구현 및 실제 검증 상태는 [화면 PLAN](Plans/SYMBOL_LOOP_PRESENTATION_PLAN.md) / [화면 REPORT](Reports/SYMBOL_LOOP_PRESENTATION_REPORT.md)를 따른다.

온라인/결제/Firebase/PvP, 다중 적, 이동값 선택, 주사위 제작, 최대 4개 이상, 일반 트리거 엔진, v1 런 이어하기/변환은 구현하지 않는다.
출시 경제와 난이도는 이번 기능 검증으로 확정하지 않는다.

## Mock 권한 분리 P1 기준과 보존 정책 (2026-10-21)

- `protocolVersion=1`, `rulesVersion=symbol-loop-mvp-1`. 현재 12칸·3지역·1~3눈 콘텐츠와 RNG를 동결한다. 조건부 3/4눈 상위 기술은 보류한다.
- 영구 재화·성장과 새 런 승인은 IGameBackend가 담당한다. Unity의 profile은 캐시/표시이며 제출된 최종 승리·HP·재화를 지급 근거로 받지 않는다.
- 개발 계정은 최초 생성 시 성장 확인용 20재화를 한 번 받는다. P1에서 이미 제출한 런 기록은 PendingVerification/지급 0을 유지한다. P2 이후 새 제출은 아래 재현 정산을 적용한다. 제출 이후 다음 런은 가능하다.
- 권한 성장 비용은 Mock에서 계산한다. Mock 프로필/재화는 운영 데이터로 승격하지 않는다. 프로세스 내부 Mock은 보안 서버가 아니다.
- 서버 요청 전 동일 ID/본문을 디스크에 보존한다. 응답 유실·타임아웃·승인 후 기기 저장 실패는 같은 요청을 조회/재전송한다. 미결 요청이 있으면 새 ID 발급/임의 취소하지 않는다.
- 로컬 백업을 복원해도 권한 프로필은 서버에서 다시 조회한다. 백업에 없는 활성 승인 런은 시작 티켓으로 복구하고, 같은 런의 남아 있는 진행/명령 로그는 유지한다. 손상된 Mock 권한 파일은 자동 초기화/과거 재화로 복원하지 않는다.
- Firebase 선택은 현재 명시적 미지원이다. 정산 복구/동시성은 아래 P3 계약을 적용한다. Firebase/Emulator(P4), Android 출시 검증(P5)은 [로드맵](Dice_Warrior_Next_Work_MockBackend_Firebase_Roadmap_v0.1.md)의 후속 범위다.

## P2 명령 재현과 보상 정산 (2026-10-21)

Mock 권한 저장소의 시작 티켓(시드·규칙·출전·성장)으로 새 Run을 구성하고 `travel/combat/choose/lap/abandon` 로그를 순서대로 실행한다. 클라이언트의 최종 상태·승리·주사위 눈·지급액은 입력으로 받지 않는다. 명령별 순번, 고유 ID, `지역:위치:단계:턴` 대상, 비용·선택·장비 슬롯·종료 여부를 확인한다. Session과 검증기는 순수 명령 규칙을 공유하되 서로 다른 상태를 사용한다.

결과 단계까지 합법적으로 재현되면 완료 지역/승리에서 지급액을 계산한다. 프로필, 영수증, 런 종료와 요청 결과는 기존 Mock 원자 저장으로 함께 확정한다. 동일 요청이나 같은 런 재제출은 추가 지급 없이 기존 영수증을 돌려준다. 승인 영수증에는 검증 버전 `symbol-loop-replay-1`과 재현된 결과를 보관한다. 규칙 버전 `symbol-loop-mvp-1`과 기존 경제/전투 계산은 그대로다.

검증 거절은 활성 런과 재화를 보존하고 실패 코드·명령 순번을 표시한다. 같은 요청 ID의 내용은 바꿀 수 없으며 정정 로그 제출은 새 요청 ID를 사용한다. 요청 상한은 2048명령/512KiB, 권한 측 60초 창의 시작 10회·새 제출 20회·포기 10회다. 같은 ID 재시도와 기존 영수증 조회는 빈도를 추가 소모하지 않는다.

고정 시드 33/51/19/1의 승리·패배·포기·상점/교체 기록과 각 명령 이후 주요 상태/RNG를 JSON으로 동결한다. 2·3기호 조합과 직렬화 재개도 비교한다. 구현·증거는 [P2 PLAN](Plans/SERVER_RUN_REPLAY_VALIDATION_PLAN.md) / [P2 REPORT](Reports/SERVER_RUN_REPLAY_VALIDATION_REPORT.md)를 따른다.

이 검증은 불법 상태 전이와 결과값 위조를 거절한다. 합법적인 다른 행동 로그를 구성하거나 미래를 예측하는 자동 플레이까지 판별하지는 못한다. 프로세스 내부 Mock 파일/코드 변조 방어와 운영 서버 보안은 Firebase 이전 및 별도 검증 범위다.

## P3 정산·비동기 복구·동시 실행 (2026-10-21)

정산 전 요청 ID와 본문을 디스크에 저장한다. 응답 유실·단절·취소 시 지급 결과를 미확정으로 표시하고 같은 요청을 조회/재전송한다. 요청 본문이 바뀌면 거절한다. 서버에서 지급했어도 로컬 저장이 끝나지 않았다면 같은 영수증을 복구하며 추가 지급하지 않는다. 이미 로컬 확정까지 끝난 뒤 최신 프로필 조회만 실패한 경우에는 승인 결과를 유지하고 재조회를 안내한다.

읽기 전용 런 조회는 시작 티켓·원 제출 영수증·저장된 명령과 최신 프로필을 반환한다. 과거 백업이 정산 전 상태라면 승인 명령을 재현해 결과를 복구한다. 기존 P1 대기 영수증은 새 검증/지급 없이 그대로 보존한다. 서버가 다음 런을 시작한 경우 이전 런 정산을 먼저 합치고 새 활성 런의 시작 티켓을 복원한다. 교체되는 로컬 원문은 `.reconciled-<id>.json`에 보존한다. 같은 활성 런의 남아 있는 로컬 진행은 유지한다.

같은 런의 동시 제출은 영수증 한 개와 지급 한 번으로 끝난다. 서로 다른 세션의 같은 revision 구매 또는 구매/정산 경합은 한 변경만 승인하고 패자는 최신 상태를 다시 읽는다. 로컬 저장은 같은 경로의 잠금과 revision/generation 비교를 사용한다. 자동 pending 정리는 관찰한 ID만 대상으로 하므로 새 입력을 지우지 않는다. 오래된 권한 응답은 최신 프로필과 완료 런을 덮을 수 없다.

화면은 정산 중/결과 불명에 `보상 검증 대기`를 표시하며 확정 전 지급 성공으로 표시하지 않는다. pause/disable 뒤 재개와 화면 재생성에서도 미결 요청은 남고, 같은 요청 확인 후 승인 결과 화면으로 돌아간다. 오류 진단에는 원 요청·응답·실제 예외를 보존한다.

P3 당시 검증 범위는 같은 프로세스의 독립 로컬 체크포인트 두 개와 공유 Mock 권한 저장소였다. 실제 네트워크 대신 전송 전/지급 후 단절·취소를 주입했다. 별도 프로세스가 동일 Mock JSON 파일을 직접 공유하는 구성은 지원하지 않는다. 당시 승인은 P3까지였으며 증거는 [P3 PLAN](Plans/SERVER_SETTLEMENT_SAFETY_PLAN.md) / [P3 REPORT](Reports/SERVER_SETTLEMENT_SAFETY_REPORT.md)에 보존한다. 이후 승인된 HTTP/SQLite 작업은 아래 M0~M3 계약으로 구분한다.

## 독립 Mock 서버 M0~M3 (2026-10-22)

사용자 승인 범위는 별도 서버·SQLite·Unity HTTP 연결까지다. 같은 저장소의 `Server/`에 ASP.NET Core 호스트, 권한 서비스/검증기, SQLite 저장소를 둔다. 서버는 Unity 설치 없이 별도 프로세스로 실행한다. Domain 소스와 LoopJson을 링크 컴파일하며 게임 규칙·프로토콜·골든 벡터는 유지한다. 버전별 서버 콘텐츠 JSON과 Unity Config의 동치를 검사한다.

Unity의 기본 백엔드는 HttpMock이다. 프로필·런 시작·제출·성장·작업 조회·런 조회의 6개 HTTP 경로를 사용하며, 즉시 이동/전투는 로컬에서 처리한다. 개발 계정은 루프백 헤더로 선택한다. Editor/개발 빌드와 서버 Development 환경에서만 허용한다. 응답 유실·취소·서버 재시작 후에도 기존 요청 ID/본문을 보존하고 영수증을 다시 확인한다. 자동 인프로세스 전환은 없다.

SQLite는 WAL과 사용자별 저장 버전 비교를 사용한다. 런 재현은 쓰기 트랜잭션 밖에서 수행하고, 짧은 트랜잭션 안에서 최신 버전과 유니크 키를 확인하여 프로필·런·영수증·작업을 함께 확정한다. 같은 DB의 복수 서버 프로세스를 검사한다. 구형 파일 권한 저장소는 Editor 회귀 검사 전용 DLL로만 남기고 플레이어에는 포함하지 않는다.

기존 P1 대기0/개발 계정 최초20 정책과 P2/P3 정산·복구 의미를 유지한다. 기존 실제 저장을 새 서버 DB로 자동 이관하지 않는다. M0~M3 당시 후속이던 계측·비용은 아래 M4로 추가 승인됐다. [M0~M3 PLAN](Plans/STANDALONE_MOCK_SERVER_01_PLAN.md) / [REPORT](Reports/STANDALONE_MOCK_SERVER_01_REPORT.md)의 완료 증거는 보존한다.

## M4 사용량·비용 확인 (2026-10-22)

별도 서버의 /dev/dashboard에 로컬 HTTP·SQLite·재현 벽시계·프로세스/파일 실측, Firestore 문서 접근 가정, 운영 실측 없음의 세 범주를 구분한다. 계측 실패가 지급 결과를 바꾸지 않고, 응답 유실과 권한 승인도 각각 보존한다. 원본 신원·요청/런 ID·명령 내용 없이 가명 메타데이터만 유한 보관한다.

서울 Firestore Standard/USD·무료 할당량 미차감을 기본으로 최소/기준/최악 비용 시나리오를 계산한다. 실제 Firebase 연결이나 운영 과금/성능 측정이 아니며 게임 경제·보상·규칙·프로토콜을 변경하지 않는다. 가격/무료 구간·전송·저장·Cloud Run 가정과 제외 비용을 명시하고 미지원/결과 불명은 미산정으로 둔다. [M4 PLAN](Plans/STANDALONE_MOCK_METRICS_04_PLAN.md) / [REPORT](Reports/STANDALONE_MOCK_METRICS_04_REPORT.md)와 [서버 안내](../Server/README.md)를 따른다. M5 규모별 부하 시험·실제 Firebase·Android는 후속 범위다.
