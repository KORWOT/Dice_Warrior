# Unity 플레이 작업실

2026-09-08 · D:/UnityProject/Dice_Warrior · Unity 6000.6.0f1.

## 사용 방법
1. Unity 메뉴 **Fate Dice > 플레이 작업실**을 연다. 제작 씬의 Scene Entry Inspector에서도 해당 씬 작업실을 열 수 있다.
2. 시작 지점·시드·시련 카드·탐험 등급 상한·화면 비율을 선택한다. 타이틀, 로비, 탐험 지도, 탐험 카드, 전투, 상점, 보상, 장비 선택, 결과의 9개 지점을 제공한다.
3. **상황 미리보기**는 Play 없이 실제 원본 화면과 규칙 결과를 표시한다. 720×1280 / 720×1600을 지원한다. 미리보기는 저장되지 않는 별도 Stage이며, 배치 수정은 **UI 원본 편집**에서 한다. 동적으로 생성되는 카드·목록은 미리보기에서 보이고, 원본 Prefab Stage에는 고정 배치와 참조가 보인다.
4. **격리 플레이 시작**으로 해당 상황에서 실제 게임을 조작한다. 매 실행은 Library/FateDiceWorkbench 아래 새 저장 슬롯을 사용한다. **플레이 중지** 시 원래 제작 씬 구성을 복원한다.
5. **게임 규칙 / 수치**, **그림 / 색상**, **앱 / 씬 연결**, **화면 등록 / 레이어**로 원본을 찾는다. 게임 설정 변경은 새 여정·새 미리보기에 반영되고 기존 저장은 시작 당시 설정을 유지한다.

## 구조와 범위
런타임 게임 규칙·컨트롤러·저장 형식은 변경하지 않았다. 신규 Editor 코드 4개와 검사 코드 1개, EditMode assembly의 Unity.ugui 참조를 추가했다. Preview는 실제 UIManager/원본 8종 화면을 한 번 바인딩하며 App/Controller/EventSystem/게임 콜백/저장소를 만들지 않는다. 닫으면 전체 clone과 Preview scene이 폐기된다.
전투·상점·보상·장비 지점은 테스트용 설정 복사본의 사건 확률을 고정한다. 결과 지점은 복사본의 능력치로 실제 패배를 생성한다. 창에 이 보정을 명시한다. 현재 입력된 설정으로 상황을 만들 수 없으면 설명을 표시하며 시작하지 않는다.
씬·프리팹에 저장되지 않은 변경이 있으면 임의로 버리지 않는다. BeforeSceneLoad에서 1회 요청을 소비한 뒤 전용 저장소를 Bootstrap에 주입한다. 초기화 실패 시 SceneEntry를 먼저 비활성화하고 Play를 중단한다. 현재 프로젝트의 domain/scene reload 비활성 옵션(3)은 변경하지 않았다.

## 실행 검증
- 최초 RED: 미구현 Preview API 검사 1건이 실제 실패했다. 신규 검사 6건 모두 통과 후 전체 최종 회귀를 실행했다.
- 최종 EditMode **128/128 PASS**. 9개 시작 상태 Save/Load·결정성·입력 검증, 원본 8종 UI 두 비율의 한글·텍스트 mesh·표시 높이, Preview 수명·원본/저장 보존 포함.
- 최종 PlayMode **57/57 PASS**, 61.96초. 기존 씬 연결·전투 배치·포인터 입력·규칙·저장·한글 UI 회귀를 포함한다.
- 현재 옵션 3에서 전투·상점 연속 native 시작/중지: 저장 경로 서로 다름, pending=false, error 빈 문자열, Title clean 복원, 앱 누수 0.
- 손상된 **테스트 전용** checkpoint를 시작 요청 후 주입: 실제 BeforeSceneLoad에서 실패, Play=false/Title clean/Entry enabled/앱 0/pending·active·setup 빈 값. 기본 저장 해시 보존.
- PWB-01: 오래된 Setup만 남긴 일반 Title Play 종료는 수정 전 Lobby로 잘못 복원(RED), 수정 후 Title과 Setup 기록 유지(GREEN). 자동 복원 소유권을 이번 Pending/Active로 제한했다.
- 비상 중단 분기 복원은 실행 중 시험 요청과 EnteredPlayMode callback을 명시적으로 주입하여 확인했다. Active 보존 후 실제 종료에서 Entry·Title 복원. 이 검사는 자연 발생 초기화 실패의 재현과 구분한다.
- APK/기기 빌드 검증은 이번 Editor 도구 작업 범위에 포함하지 않았다.

## 사용성 관찰과 후속 제안
작업실 상태 갱신 지연을 수정하고 Preview의 Scene 격자는 임시로 숨겼다. 테스트 종료 시 이전 씬으로 돌아가며 수정할 원본을 직접 찾을 수 있어 매번 처음부터 플레이할 필요가 줄었다.
탐험 운명 카드와 상점 나가기 등이 화면 아래 스크롤에 놓여 있어 처음에는 발견하기 어렵다. 실제 스크롤/클릭은 동작했다. 다음 화면 배치 개선에서는 스크롤 가능 표시를 추가하고 **상점 나가기**를 고정 하단에 두는 것이 좋다. 게임 규칙이나 해당 화면 레이아웃은 이번 작업에서 추가 개편하지 않았다.

## 보존 경계와 알려진 차이
기본 저장 파일의 SHA256는 작업 시작과 동일하다. 제작 Title/Lobby/InGame scene, 설정 SO·카탈로그·폰트·기타 프리팹·기존 런타임 코드·Packages/ProjectSettings의 바이트를 baseline과 비교한다. 이전 사용자 변경은 유지했다. 커밋/브랜치 생성은 하지 않았다.
**CombatUI.prefab 예외:** 원본 편집 버튼 테스트 시 Unity Prefab Stage가 15:14:55에 이 파일을 재저장했다. 레이아웃을 변경하는 직접 입력은 수행하지 않았으나 baseline 해시와 달라 이 파일의 바이트 보존은 주장하지 않는다. 원본 바이트 백업이 없어 정확한 직렬화 필드 차이는 확인하지 못했다. 임의 재구성으로 덮어쓰지 않고 현재 파일에 대한 전체 전투/한글 회귀 결과와 함께 남긴다. meta/GUID는 보존되었다.

검토는 최초1묶음+필수 Finding 수정·재검증2묶음으로 종료했다. 실행 원본 증거는 작업 staging의 artifacts/play-workbench/{final-edit,final-play,native-combat-menu,native-shop-complete,native-stop1,native-stop2,failclosed-result,stale-red-result,stale-green-result,emergency-result,boundary-final}.json에 있다. staged 초안의 NOT_RUN 표시는 최종 증거로 치환하였다.
